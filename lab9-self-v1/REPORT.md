# Самостійна робота №15

**Тема:** Делегати й лямбда-вирази: власні утиліти для колекцій.

**Виконав:** Галушко Богдан Миколайович.

## Що зроблено

Я створив статичний клас CollectionUtils із чотирма узагальненими методами:

- Map — перетворює кожен елемент.
- MaxBy — знаходить елемент із найбільшим значенням вибраного ключа.
- Filter — відбирає елементи за умовою.
- ForEach — виконує дію для кожного елемента.

Для перевірки використав три колекції: List<int>, List<string> і List<Product>. Кожен метод викликав із різними лямбда-виразами.

## 1. Чому делегати корисні для таких утиліт?

Делегати дозволяють передати в метод потрібну дію або умову. Завдяки цьому один метод можна використовувати для різних задач, не переписуючи його код.

У програмі Func повертає результат, Predicate перевіряє умову та повертає bool, а Action виконує дію без повернення результату.

## 2. Як лямбда-вирази спрощують виклик методів?

Лямбда-вирази дозволяють коротко записати потрібну логіку прямо під час виклику методу.

Наприклад, n => n * n обчислює квадрат числа, а p => p.Price > 1000 перевіряє ціну товару. Для цього не потрібно створювати окремі іменовані методи.

## 3. Порівняння з LINQ

| Власний метод | Вбудований аналог | Призначення |
|---|---|---|
| Map | Select | Перетворення елементів |
| MaxBy | MaxBy | Пошук елемента з найбільшим ключем |
| Filter | Where | Відбір за умовою |
| ForEach | List<T>.ForEach або цикл foreach | Виконання дії для кожного елемента |

List<T>.ForEach є методом списку, а не оператором LINQ.

Мої Map і Filter одразу створюють список результатів. Select і Where використовують відкладене виконання: обробляють елементи під час перебору результату.

Мій MaxBy для порожньої колекції повідомляє про помилку через виняток.
