# Самостійна робота №14

**Тема:** Вивчення Dictionary<TKey, TValue> та HashSet<T> у бібліотеках .NET.



## Частина 1. Аналіз використання колекцій у відкритих проєктах

Я розглянув два приклади використання колекцій у бібліотеці System.Linq з відкритого проєкту .NET Runtime.

### 1. Використання Dictionary<TKey, TValue>

**Джерело:** [ToCollection.cs — метод ToDictionary](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs).

**Контекст.** Метод ToDictionary перетворює послідовність елементів на словник. Кожному елементу призначається ключ, за яким можна отримати його значення. Наприклад, ключем може бути номер студента, а значенням — інформація про нього.

**Чому обрано Dictionary.** Словник дозволяє швидко знаходити значення за ключем. У List або масиві для пошуку студента за номером потрібно було б перебирати елементи.

**Складність операцій:**

- Пошук за ключем — у середньому O(1).
- Додавання — амортизовано O(1).
- Видалення за ключем — у середньому O(1).
- Створення словника з n елементів — у середньому O(n).

**Особливі вимоги.** Ключі повинні бути унікальними й не можуть бути null. Повторний ключ під час виконання ToDictionary спричиняє помилку. Можна передати власний IEqualityComparer<TKey>, який визначає правила порівняння ключів.

### 2. Використання HashSet<T>

**Джерело:** [Distinct.cs — клас DistinctIterator](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/Distinct.cs).

**Контекст.** Метод Distinct прибирає повтори з послідовності. HashSet зберігає вже знайдені елементи. Якщо метод Add повертає true, елемент зустрівся вперше й потрапляє до результату.

**Чому обрано HashSet.** Він зберігає лише унікальні елементи та швидко перевіряє їхню наявність. У List або масиві довелося б щоразу перебирати вже знайдені значення.

**Складність операцій:**

- Перевірка наявності — у середньому O(1).
- Додавання — амортизовано O(1).
- Видалення — у середньому O(1).
- Обробка n елементів методом Distinct — у середньому O(n).

**Особливі вимоги.** Можна передати власний IEqualityComparer<T>. Наприклад, StringComparer.OrdinalIgnoreCase дозволяє вважати однаковими слова з різним регістром. Рівні елементи повинні мати однаковий хеш.

## Частина 3. Порівняльна таблиця

| Операція | List<T> | Dictionary<TKey, TValue> | HashSet<T> | Коли використовувати |
|---|---|---|---|---|
| Додавання | O(1)* | O(1)* | O(1)* | List — для послідовності з можливими повторами; Dictionary — для пар «ключ — значення»; HashSet — для унікальних елементів |
| Пошук за значенням | O(n) | N/A** | O(1) | HashSet — для швидкого пошуку самого елемента; List — якщо потрібні також індекси й повтори |
| Пошук за ключем | N/A | O(1) | N/A | Dictionary — для отримання значення за відомим ключем |
| Видалення | O(n) | O(1) | O(1) | Dictionary — видалення за ключем; HashSet — за елементом; List — зі збереженням порядку решти елементів |
| Перевірка наявності | O(n) | O(1) | O(1) | List.Contains — перевірка значення; Dictionary.ContainsKey — ключа; HashSet.Contains — елемента |

**Примітки:**

- n — кількість елементів у колекції.
- Для Dictionary і HashSet наведено середню складність операцій.
- *Додавання має амортизовану складність O(1). Під час збільшення місткості окреме додавання може зайняти O(n).
- Додавання до List означає додавання в кінець через Add. Вставлення всередину списку має складність O(n).
- Видалення означає List.Remove за значенням, Dictionary.Remove за ключем і HashSet.Remove за елементом.
- **N/A у рядку пошуку за значенням залишено відповідно до шаблону завдання. Dictionary має метод ContainsValue, але він виконує пошук за O(n).
- Через колізії хешів операції Dictionary і HashSet у найгіршому випадку можуть мати складність O(n).
- Оцінки наведено без урахування окремих витрат на обчислення хешу й порівняння елементів.
